Formularios y almacenamiento

Pedir datos de verdad (sin prompt), validarlos, y lograr que no se pierdan al recargar la página.

Al terminar esta unidad vas a poder

  • Leer los valores de inputs, checkboxes y selects.
  • Manejar el envío de un formulario con submit y preventDefault().
  • Validar datos y mostrar errores en la página.
  • Convertir datos a texto y de vuelta con JSON.
  • Guardar datos en el navegador con localStorage.
  • Manejar errores con try/catch.

Leer los datos de un formulario

<form id="form-registro">
  <label for="nombre">Nombre</label>
  <input id="nombre" type="text" />

  <label for="edad">Edad</label>
  <input id="edad" type="number" />

  <label for="curso">Curso</label>
  <select id="curso">
    <option value="js">JavaScript</option>
    <option value="py">Python</option>
  </select>

  <label><input id="novedades" type="checkbox" /> Quiero recibir novedades</label>

  <button type="submit">Enviar</button>
</form>
const nombre = document.querySelector("#nombre").value;     // string
const edad = Number(document.querySelector("#edad").value); // ¡convertir!
const curso = document.querySelector("#curso").value;       // "js" o "py"
const novedades = document.querySelector("#novedades").checked; // true o false

.value siempre es un string, aunque el input sea type="number". Es el mismo problema que con prompt: convertí con Number() antes de hacer cuentas. En los checkboxes no se usa .value sino .checked.

El evento submit

Podrías escuchar el click del botón, pero es mejor escuchar el submit del formulario: así también funciona al apretar Enter en cualquier campo, y el navegador aplica las validaciones del HTML. 

const form = document.querySelector("#form-registro");

form.addEventListener("submit", (e) => {
  e.preventDefault(); // evita que la página se recargue

  const nombre = document.querySelector("#nombre").value.trim();
  console.log(`Registrado: ${nombre}`);

  form.reset(); // vacía todos los campos
});

Si te olvidás de e.preventDefault(), el formulario hace lo que hacía en HTML puro: envía los datos y recarga la página. Vas a ver tu mensaje en la consola durante una fracción de segundo y después desaparece.

Validar

Primero, el HTML

Muchas validaciones las hace el navegador solo, con atributos que ya conocés. Si un campo no cumple, el evento submit ni siquiera ocurre: 

<input id="nombre" required minlength="2" />
<input id="edad" type="number" required min="16" max="99" />
<input id="email" type="email" required />

Después, JavaScript

Para reglas propias (que dos contraseñas coincidan, que una fecha sea futura…) validamos en el submit y mostramos el error en la página, al lado del campo, no con un alert: 

<input id="clave" type="password" required />
<input id="clave2" type="password" required />
<p id="error" class="error"></p>
form.addEventListener("submit", (e) => {
  e.preventDefault();

  const clave = document.querySelector("#clave").value;
  const clave2 = document.querySelector("#clave2").value;
  const error = document.querySelector("#error");

  if (clave.length < 8) {
    error.textContent = "La contraseña debe tener al menos 8 caracteres";
    return; // cortamos acá: no seguimos con el registro
  }
  if (clave !== clave2) {
    error.textContent = "Las contraseñas no coinciden";
    return;
  }

  error.textContent = "";
  console.log("¡Registro exitoso!");
});

Validar en el navegador mejora la experiencia, pero no es seguridad: cualquiera puede saltearse tu JavaScript. En un sistema real, el servidor vuelve a validar todo.

JSON

JSON (JavaScript Object Notation) es un formato de texto para guardar y enviar datos. Se parece muchísimo a un objeto de JavaScript, pero es un string. Es el idioma en el que se comunican casi todas las aplicaciones web (lo vamos a volver a ver en la Unidad 8). 

const alumno = { nombre: "Ana", edad: 25, cursos: ["HTML", "JS"] };

// Objeto → texto JSON
const texto = JSON.stringify(alumno);
console.log(texto);        // '{"nombre":"Ana","edad":25,"cursos":["HTML","JS"]}'
console.log(typeof texto); // "string"

// Texto JSON → objeto
const deVuelta = JSON.parse(texto);
console.log(deVuelta.cursos[1]); // "JS"

Reglas del formato JSON:

  • Las propiedades van siempre entre comillas dobles.
  • Acepta strings, números, booleanos, null, arrays y objetos. No acepta funciones ni undefined.
  • No admite comas al final ni comentarios.

localStorage

Es un pequeño almacén del navegador donde tu página puede guardar datos que sobreviven a recargar y a cerrar el navegador. Funciona con pares clave → valor: 

localStorage.setItem("nombre", "Ana");     // guardar
localStorage.getItem("nombre");            // "Ana"
localStorage.getItem("noExiste");          // null
localStorage.removeItem("nombre");         // borrar una clave
localStorage.clear();                      // borrar todo

localStorage solo guarda strings. Un número vuelve como texto, y un array u objeto se arruina: 

localStorage.setItem("compras", ["pan", "leche"]);
localStorage.getItem("compras"); // "pan,leche" 😬 ya no es un array

La solución es combinarlo con JSON:

const compras = ["pan", "leche"];

// Guardar: array → JSON
localStorage.setItem("compras", JSON.stringify(compras));

// Leer: JSON → array (si no había nada, usamos un array vacío)
const guardadas = JSON.parse(localStorage.getItem("compras")) || [];

En DevTools, pestaña Application → Local Storage, ves todo lo que guardó tu página y lo podés editar o borrar a mano.

Cada sitio tiene su propio localStorage (unos 5 MB) y solo existe en ese navegador y esa computadora. No guardes contraseñas ni datos sensibles: cualquier script de la página lo puede leer.

Manejar errores con try/catch

Algunas operaciones pueden fallar aunque tu código esté bien. Por ejemplo, JSON.parse lanza un error si el texto no es JSON válido (alguien lo editó a mano, o lo guardó otra versión de tu app). Sin manejo, ese error frena todo el script. 

try {
  // código que puede fallar
  const datos = JSON.parse("{esto no es json}");
  console.log(datos);
} catch (error) {
  // se ejecuta solo si algo falló dentro del try
  console.error("No se pudieron leer los datos:", error.message);
}

console.log("El programa sigue funcionando 👍");

También podés lanzar tus propios errores con throw:

function dividir(a, b) {
  if (b === 0) {
    throw new Error("No se puede dividir por cero");
  }
  return a / b;
}

try {
  dividir(10, 0);
} catch (error) {
  console.log(error.message); // "No se puede dividir por cero"
}

  • El bloque finally en un try/catch.

Ejemplo completo: lista de tareas que se guarda

Juntamos todo con el patrón de la Unidad 6: los datos viven en un array, y cada vez que cambian, los guardamos y volvemos a dibujar.

index.html

<form id="form-tarea">
  <label for="texto">Nueva tarea</label>
  <input id="texto" required maxlength="80" />
  <button type="submit">Agregar</button>
</form>

<ul id="lista"></ul>

style.css

.hecha span {
  text-decoration: line-through;
  opacity: 0.6;
}

script.js

const form = document.querySelector("#form-tarea");
const input = document.querySelector("#texto");
const lista = document.querySelector("#lista");

let tareas = [];

// ---------- Datos ----------
function cargarTareas() {
  try {
    return JSON.parse(localStorage.getItem("tareas")) || [];
  } catch {
    // (sin "(error)": no necesitamos saber qué falló)
    return []; // si lo guardado está roto, empezamos de cero
  }
}

function guardarTareas() {
  localStorage.setItem("tareas", JSON.stringify(tareas));
}

// ---------- Pantalla ----------
function mostrarTareas() {
  lista.innerHTML = "";

  tareas.forEach((tarea) => {
    const li = document.createElement("li");
    li.dataset.id = tarea.id;
    li.classList.toggle("hecha", tarea.hecha);

    const texto = document.createElement("span");
    texto.textContent = tarea.texto;

    const btnHecha = document.createElement("button");
    btnHecha.textContent = tarea.hecha ? "Deshacer" : "Hecha";
    btnHecha.dataset.accion = "alternar";

    const btnBorrar = document.createElement("button");
    btnBorrar.textContent = "Borrar";
    btnBorrar.dataset.accion = "borrar";

    li.append(texto, btnHecha, btnBorrar);
    lista.append(li);
  });
}

// ---------- Eventos ----------
form.addEventListener("submit", (e) => {
  e.preventDefault();
  const texto = input.value.trim();
  if (texto === "") return;

  tareas.push({ id: Date.now(), texto: texto, hecha: false });
  guardarTareas();
  mostrarTareas();

  form.reset();
  input.focus();
});

lista.addEventListener("click", (e) => {
  const boton = e.target.closest("button");
  if (!boton) return;

  const id = Number(boton.closest("li").dataset.id);

  if (boton.dataset.accion === "borrar") {
    tareas = tareas.filter((t) => t.id !== id);
  } else if (boton.dataset.accion === "alternar") {
    const tarea = tareas.find((t) => t.id === id);
    tarea.hecha = !tarea.hecha;
  }

  guardarTareas();
  mostrarTareas();
});

// ---------- Inicio ----------
tareas = cargarTareas();
mostrarTareas();

Date.now() devuelve la cantidad de milisegundos desde 1970. Como nunca se repite entre dos clics, es una forma simple de generar un id único.

Práctica

1 · Formulario de inscripción

Nombre, email, edad (16 a 99), curso (select) y un checkbox de “acepto los términos”. Validá con atributos HTML y, con JavaScript, que el checkbox esté marcado. Al enviar, ocultá el formulario y mostrá un mensaje: “¡Gracias, Ana! Te inscribiste en JavaScript”.

2 · Recordar preferencias

Al ejercicio del modo oscuro de la Unidad 6, agregale que recuerde la elección del usuario al recargar. Agregá también un input “¿Cómo te llamás?” y que, si ya lo ingresó antes, la página lo salude por su nombre.

3 · Mejorar la lista de tareas

A partir del ejemplo completo:

  • Mostrá “Te quedan 3 tareas pendientes” (o “¡No hay tareas pendientes! 🎉”).
  • Agregá botones de filtro: Todas / Pendientes / Hechas.
  • Agregá un botón “Borrar hechas”.
  • Si la lista está vacía, mostrá un mensaje en lugar de la lista.

4 · Control de gastos (integrador)

Una app para anotar gastos personales:

  • Formulario con descripción, monto (mayor a 0) y categoría (select: comida, transporte, ocio, servicios).
  • Listado de gastos con la fecha en que se cargó y un botón para borrar cada uno.
  • Total general y total por categoría, formateados como moneda.
  • Un filtro por categoría.
  • Todo se guarda en localStorage.
Pista

Cada gasto puede ser un objeto { id, descripcion, monto, categoria, fecha }. La fecha guardala como número con Date.now() (las fechas no se guardan bien en JSON) y convertila con new Date(gasto.fecha) al mostrarla.
